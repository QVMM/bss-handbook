需求分析与 UML 设计

省赛样卷没有单独的“画图”任务，但每一道开发题都要先读懂需求、理清数据和流程，才能写得又快又对。UML（统一建模语言）就是把这些想法画出来的通用画法。WorldSkills 的专家能力要求中明确列出了 UML 等系统分析与设计方法，走向国赛、世赛，这一章是必修课。标准版 1 周，强化版穿插在模拟训练中完成。

01为什么要先画图再写代码

  • 读题更准：把一段文字需求画成用例图、流程图，漏掉的条件会自己“冒出来”（例如“如果手机号已注册怎么办？”）。
  • 写得更快：数据库表和接口一旦在图上定好，桌面端、接口、手机端可以照着写，不会写到一半推倒重来。
  • 评价分：判断分（评价分）看重“作品是否专业”。清晰的接口文档、ER 图、操作手册里的流程图，都是专业度的直接体现。
  • 团队沟通：企业中需求、开发、测试三方就是靠这些图对齐理解的。
训练建议：比赛中画图用多少时间

比赛时不需要画精美的图。拿到题目后用 5–10 分钟在草稿纸上画出：实体和关系（简易 ER 图）、页面跳转图、接口清单。这 10 分钟往往能省下后面一个小时的返工。平时训练时则要用工具认真画，练出“看到需求就能想到图”的能力。

03用例图：系统给谁用、能做什么

用例图回答两个问题：谁（参与者 Actor，小人图标）使用系统，能做什么（用例 Use Case，椭圆）。系统边界用方框表示。

智慧康养平台用例图（文字版）
                ┌──────────────── 智慧康养平台 ────────────────┐
                │                                              │
   管理员 ──────┼──( 登录 )                                     │
     │          │──( 管理客户 )──«include»──( 查询客户 )       │
     │          │──( 管理服务 )                                 │
     │          │──( 处理投诉 )                                 │
     └──────────┼──( 查看统计 )                                 │
                │                                              │
   客户 ────────┼──( 注册 )──«include»──( 获取验证码 )         │
     │          │──( 登录 )◀──«extend»──( 验证码登录 )         │
     │          │──( 预约服务 )                                 │
     │          │──( 查看订单 )◀──«extend»──( 取消订单 )       │
     │          │──( 查看健康数据 )                             │
     └──────────┼──( 紧急求助 )                                 │
                └──────────────────────────────────────────────┘
  • «include»（包含）：执行 A 时一定会执行 B。注册一定要获取验证码。
  • «extend»（扩展）：在某些条件下才执行的附加行为。查看订单时可以（但不一定）取消订单。
  • 一个用例用“动词 + 名词”命名：预约服务、处理投诉。

07ER 图与线框图

ER 图

第 05 章已经学过 ER 图和数据字典。设计时注意三件事：每个实体都有主键；一对多的“多”方放外键；多对多一定拆出中间表。湖北样题模块 A 就提供了 ERD.pdf（资料包中的赛题文档提到了它，但文件本身未包含在文档内），比赛中拿到 ER 图，第一件事是对照它在 SSMS 中看一遍表结构，确认字段名和类型。

线框图（界面草图）

辽宁通用要求写明“线框图仅供参考”：功能和数据以文字要求为准，布局可以按风格指引优化。练习时可以在纸上或 draw.io 中画线框图，标出每个控件的名称（txtPhone、btnLogin），然后照着搭界面。

08需求分析的完整流程（比赛版）

  1. 通读：完整读一遍题目，不动手，标出所有“必须”“需要”“不能”“至少”。
  2. 拆点：每句要求拆成可检查的点，写在草稿纸上（第 03 章的“拆成得分点”）。
  3. 找名词：名词往往是表或字段（客户、服务、订单、投诉、手机号、预约时间）。
  4. 找动词：动词往往是功能、接口（注册、预约、取消、回复）。
  5. 画三张草图：简易 ER 图、页面跳转图、接口清单。
  6. 排顺序：数据库 → 接口 → 界面；分值大、依赖少的先做。
  7. 补缺口：题目没写清楚的（例如样卷中“略”的部分、没给的数据），按行业常识做出合理假设，并在说明文件中写明“本作品假设……”。
练习 9-4　综合：为一个新场景做设计

场景：“社区食堂订餐平台”。管理端（桌面）：菜品管理、每日菜单、订单统计；客户端（手机）：注册登录、浏览今日菜单、下单、评价。请在 90 分钟内完成：用例图、ER 图（至少 5 张表）、数据字典、接口文档（至少 8 个接口，格式同第 07 章）、“下单”活动图。完成后对照第 15 章的“设计文档自查表”打分。
