模拟训练：样题实战与自评

学会每个知识点，和在 2 小时内把一个模块完整做完、交付、经得起裁判逐条检查，是两回事。本章教你怎样用资料包里的辽宁样卷、湖北样题和匈牙利赛题做“全真模拟”，怎样补齐样卷中省略的部分和缺失的素材，怎样像裁判一样给自己打分，以及怎样把一套样题变出更多套练习题。

02全真模拟的执行规程

全真模拟的价值在于“真”。以下规程尽量还原辽宁技术文件中的赛场要求（断网、不准带资料、连续保存、按时提交），请严格执行：

开始前（前一天）

  • 准备一台“干净”的练习机：只保留第 02 章安装的软件；关闭输入法云联想等联网功能
  • 还原数据库：执行练习库脚本，确保数据为初始状态
  • 删除桌面上旧的 Modul1 / Modul2 / Modul3 文件夹
  • 准备一个 U 盘作为“提交盘”
  • 请一位同学或老师担任“裁判”，负责发题、计时、提醒、收卷（没有人时用手机定时器）
  • 把本书、笔记、手机放到另一个房间

进行中

  1. 断网：拔掉网线 / 关闭 Wi-Fi。
  2. 发题：开始前 5 分钟拿到题目（辽宁文件规定开赛前 5 分钟发放赛题），这 5 分钟只读题，不碰键盘。
  3. 计时：每个模块 2 小时；结束前 15 分钟“裁判”提醒一次。
  4. 中途：每完成一个功能保存一次（Ctrl + Shift + S 全部保存），每 30 分钟把当前成果复制一份到桌面备份文件夹。
  5. 收卷：时间到立即停手，在规定的几分钟内完成压缩和复制到 U 盘（辽宁文件中有比赛结束后限时提交的规定，具体时限以正式赛题和赛场通知为准，训练时按 3 分钟练）。
  6. 休息：模块之间至少休息 30 分钟，与比赛节奏一致。

结束后（当天）

  1. 按本章“自评”方法打分，填写第 15 章的模拟记录表。
  2. 把每一个失分点写进错题本，标明原因：不会 / 会但慢 / 会但忘了 / 理解错题意。
  3. 第二天先把失分最多的功能重做一遍（不看原代码）。
训练建议：建立自己的“赛场节奏表”

每次单模块模拟都记录：读题用了几分钟、数据库准备用了几分钟、每个任务用了几分钟、最后检查和交付用了几分钟。三四次以后，你就能做出可靠的时间分配（例如 A 模块：读题 10、数据库与接口 25、任务 1 用 25、任务 2 和 3 各 25、自查与交付 10），比赛时按表推进。

03辽宁样卷：补齐“略”的部分

辽宁样卷的模块 A 只写出了任务 1.1（登录 / 注册，10 分），1.2、1.3（各 15 分）写的是“略”；模块 B 同样只写出了 2.1（10 分），2.2、2.3（各 15 分）为“略”。文件同时说明正式赛题由样卷调整不超过 30% 形成、考核要素基本不变。这意味着：正式赛题的大部分分值，在样卷里是看不到具体内容的。你需要依据样卷的场景介绍和能力目录，自己补出这些任务来练。

自拟的依据

  • 模块 A 的场景说明：桌面端面向平台管理者，整合康养服务资源、用户数据、订单信息及投诉反馈；1.1 要求登录成功后进入“系统首页（用户管理界面）”。
  • 模块 B：数据来源于 Modul1 接口；面向客户。
  • 能力目录中的设备性能参数、可视化统计、WebAPI、传感器、兼容性等内容。

据此，下面给出一套自拟练习任务卡（不是官方内容，只是用来练习的合理推测，分值按样卷对应任务的分值设置）。数据用本手册的 SmartCare 练习库。

自拟任务卡 A-1.2：用户管理（15 分）

  • 登录成功后进入本界面，界面顶部显示 Logo、平台名称、当前登录管理员姓名、“注销”和“退出”按钮。
  • 以表格显示客户：编号、姓名、性别、出生日期（YYYY-MM-DD）、年龄、手机号、地址、状态；姓名为空时显示“未填写”。
  • 可按姓名或手机号模糊查询，可按状态筛选，两个条件可组合。
  • 每页 10 条，有首页、上一页、下一页、尾页和页码跳转，显示总条数与当前页 / 总页数。
  • 已禁用的客户整行以浅红色背景显示，界面有颜色图例。
  • 可新增、编辑客户（手机号 11 位且唯一、姓名必填、出生日期不能晚于今天、照片不超过 100KB，没有照片显示 default.jpg）；双击行也可编辑。
  • 可禁用 / 启用客户，操作前需确认。
  • “退出”时需确认；“注销”返回登录界面。

自拟任务卡 A-1.3：服务订单与投诉（15 分）

  • 服务管理：按分类筛选、名称查询；新增 / 编辑服务（价格非负、最多两位小数）；上架 / 下架。
  • 订单管理：按状态、下单日期范围筛选；状态以中文显示并以颜色区分（附图例）；可取消“待支付 / 已支付”的订单。
  • 投诉处理：待处理的排在前面；可查看详情并回复，回复后状态变为已处理并记录回复时间，不能重复回复。
  • 统计：按月统计订单数和营业额（不含已取消），表格 + 折线图，可切换显示订单数或营业额，可选择是否在图上显示数值。
  • 为模块 B 提供接口：登录、注册、重置密码、服务查询、下单、订单查询、取消订单、健康数据、紧急联系人（地址和格式自定，写入接口文档）。

自拟任务卡 B-2.2：服务预约与订单（15 分）

  • 首页以宫格显示功能入口，顶部显示欢迎语。
  • 服务列表显示图片、名称、分类、时长、价格；可按名称搜索、按分类筛选；没有结果时有提示；没有图片显示默认图片。

  • 我的订单：显示全部订单（新的在前），状态以颜色区分；可取消待支付 / 已支付订单，需确认。

  • 健康数据：可切换血压 / 血糖 / 心率，以折线图显示（横轴日期，纵轴数值，有图例），超出警戒值的点以红色显示，下方显示最高、最低、平均和最近一次。

04像裁判一样给自己打分

第一步：把任务卡变成评分表

辽宁文件中的测量分示例，有“全对得分、否则 0 分”的项目（如 0.5 分一项），也有“缺一个要素扣 0.5 分，扣完为止”的项目（如 2 分一项）。自评时，把每张任务卡逐句拆成测量点，每个点 0.5 分，凑够任务分值。以 1.1（10 分）为例，可以这样拆（示例）：

编号测量点分值方式
M1登录界面元素齐全：Logo、标题、用户名、密码、记住密码、登录、注册入口1.0缺一项扣 0.5，扣完为止
M2用户名或密码为空时有明确提示0.5全对或 0
M3用户名或密码错误时有明确提示0.5全对或 0
M4登录成功进入用户管理界面0.5全对或 0
M5勾选记住密码，重启程序后自动填入1.0全对或 0
M6取消勾选后，重启程序不再填入0.5全对或 0
M7注册界面元素齐全1.0缺一项扣 0.5
M8用户名唯一性校验与提示1.0全对或 0
M9密码长度与组成校验与提示1.0全对或 0
M10两次密码一致性校验与提示0.5全对或 0
M11手机号 11 位校验与提示0.5全对或 0
M12注册成功写入数据库，可用新账号登录1.0全对或 0
M13注册成功后返回登录界面并有成功提示0.5全对或 0
合计9.5

这里只拆出 9.5 分，剩下的 0.5 分你会放在哪里？（提示：重读样卷 1.1 的第一句话——程序运行后首先进入哪个界面？）这样的追问，正是在训练你“把每句话都当得分点”的读题习惯。

第二步：评价分（判断分）自评

辽宁样卷模块 A、B 各有 3 分评价分。评价分采用 0–3 分的等级描述，由至少 2 名裁判独立打分，分差不超过 1 分，评价分先于测量分评判（详见第 01 章）。自评时请同学做第二位“裁判”，两人独立打分再对比：

分数通用描述（训练用）界面与体验举例
0明显低于行业标准控件随意摆放，风格混乱，多处出现 Form1、button1
1达到行业标准功能可用，布局基本整齐，但风格不统一、提示简陋
2达到行业标准，部分方面优秀风格统一、对齐规范、提示明确、操作顺手（回车登录、Tab 顺序）
3优秀，远超行业标准在 2 分基础上，细节处处考虑用户：即时校验、空状态提示、防重复提交、加载提示、一致的图标与配色

上表是训练用的通用描述，正式比赛的评价标准以赛场公布的评分细则为准。

第三步：评分顺序与记录

  1. 先做评价分（与辽宁文件规定的顺序一致），避免被测量分的结果影响整体印象。
  2. 再逐条做测量分。每一条都要实际操作验证，不能凭“我记得写过”。
  3. 换一台电脑（或新建一个 Windows 用户）运行交付的成果，确认裁判拿到后能跑起来。
  4. 把结果记入第 15 章的模拟记录表，计算得分率，和上一次比较。

湖北样题文档（第 46 届世赛湖北省选拔赛）完整描述了模块 A 的 11 个界面和模块 B 的 7 个界面，配套评分表细化到 0.1 分。但文档中提到的素材——数据库脚本、ER 图、图片、风格指引、接口程序与接口文档、宣传视频——都不在资料包中。同时它的赛场环境较旧（Visual Studio 2015、SQL Server 2014、Android Studio 2.2.3），每个模块 3 小时，且要求全部使用英文。

补齐方法

用湖北评分表自评

湖北评分表的“子评分表”工作表按界面分为 A1M、A2M……B7M 等子模块，每条细则写明了最大分值和拆分到 0.1 分的得分要素（括号中的数字）。做完一个界面，就打开评分表对应的子模块，逐个要素检查打分。这份评分表是学习“裁判怎么看作品”的最好材料：你会发现，很多分数给在你以为“不重要”的细节上（标题与输入提示、日期格式、默认选项、颜色说明）。

易错提醒：不要照搬旧环境

湖北样题的软件版本是当年的配置。练习时用你现在的环境（VS 2022、SQL Server 2022、新版 Android Studio）即可，只学它的题型和评分思路。比赛环境以你所参加比赛的技术文件为准。

06匈牙利赛题：读英文题、按文档交付

赛题内容练习要点

把 MySQL 脚本转成 SQL Server

WS2024 附带的数据库脚本是 MySQL 导出的格式，不能直接在 SSMS 中执行。它只有一张 Routes 表（54 条线路数据），转换起来不难，而且是很好的练习。逐项修改：

MySQL 写法SQL Server 写法
以 /*!40101 ... */; 开头的行、LOCK TABLES、UNLOCK TABLES整行删除
反引号 `Routes`去掉，或改为方括号 [Routes]
int(11)INT
AUTO_INCREMENT（列定义中）IDENTITY(1,1)
longtextNVARCHAR(MAX)
) ENGINE=InnoDB ... COLLATE=...;);
插入时指定了 Id 值插入前 SET IDENTITY_INSERT Routes ON;，插入语句写明列名，插入后 SET IDENTITY_INSERT Routes OFF;
字符串 'Siófok kelet'（含匈牙利语字母）加 N 前缀：N'Siófok kelet'，否则在中文排序规则的数据库中，部分字母会变成问号
文件末尾的 CREATE USER ... GRANT ...删除（SQL Server 的用户管理方式不同，练习用 Windows 身份验证即可）
（文件开头）加上 CREATE DATABASE SessionOne; 和 USE SessionOne;

转换后执行 SELECT COUNT(*) FROM Routes;，结果应为 54。字符串很多，手工加 N 前缀很费时：可以用 SSMS 或 Notepad++ 的“查找替换”（正则模式下，把 ,' 替换为 ,N'，再检查每行开头的第一个字符串）。注意 MySQL 中字符串里的 \' 在 SQL Server 中要写成两个单引号 ''。

0730% 改编法：一套样题变十套

辽宁文件说明正式赛题由样卷调整不超过 30% 形成，考核要素基本不变，但要素数量可能不同。所以最有针对性的练习，就是自己把样卷“改编”，再按改编后的要求做。改编时从下列卡片中抽 3–5 张，替换样卷中的对应要求：

#改编卡举例
1换校验规则密码改为“8–16 位，必须含大写字母、小写字母和数字”
2换唯一性字段用户名唯一 → 手机号唯一 + 身份证号唯一
3加一个输入项注册时增加“身份证号”，并据此自动计算出生日期和性别
4换记住方式记住密码 → 7 天内自动登录

08自造一套全新的题

模拟阶段后期，建议至少做一套“全新场景”的题，检验你是否真的掌握了方法，而不是记住了 SmartCare 的代码。自造题目的步骤：

  1. 选场景：从改编卡 #20 中选，或从生活中找（图书借阅、社区团购、驾校预约）。
  2. 设计数据库：5–8 张表，写建表脚本，造 50–100 条数据（含禁用账号、空值、已下架、已取消等“特殊数据”）。可以用 Excel 编数据，再拼成 INSERT 语句。
  3. 按样卷结构写题：A 模块 3 个任务（10 / 15 / 15 分），B 模块 3 个任务（10 / 15 / 15 分），C 模块用例与手册（10 / 10 分）。
  4. 写评分表：按本章方法拆成测量点。
  5. 交换做题：和同学互换各自出的题，限时完成后互相评分。
训练建议：出题本身就是训练

写题和写评分表时，你会第一次站在裁判的角度思考“这句话怎么检查”。这种视角转换，比多做一套题更能提高你读题和自查的能力。
