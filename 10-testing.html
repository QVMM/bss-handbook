02测试的基本概念

术语解释
测试用例一次测试的完整描述：在什么前提下、做什么操作、应该得到什么结果。好的用例别人拿去照着做，结果应该一样
黑盒测试不看代码，只根据功能需求，从使用者角度测试。模块 C 就是黑盒测试
白盒测试看着代码设计测试，让每个分支都被执行到。单元测试属于白盒
功能测试功能是否符合需求
兼容性测试不同屏幕、系统版本、横竖屏下是否正常
缺陷（Bug）实际结果与预期结果不一致
回归测试修改代码后，把以前通过的用例再跑一遍，确认没有改坏

03设计用例的四种方法

1. 等价类划分

把所有可能的输入分成几类，每类里挑一个代表就够了。以“手机号：11 位数字”为例：

类别代表值预期
有效：11 位数字13800000001通过
无效：为空（空）提示不能为空
无效：位数不对1380000提示格式错误
无效：含非数字1380000000a提示格式错误（或无法输入）

2. 边界值分析

错误最常出现在边界上。对“密码至少 8 位”，要测 7 位、8 位、9 位；对“验证码 1 分钟有效”，要测 59 秒和 61 秒；对“每页 10 条”，要测正好 10 条、11 条、0 条。

3. 场景法（业务流程）

按用户真实的使用路径串起来测：注册 → 登录 → 预约 → 查看订单 → 取消 → 退出登录。每条路径一个“正常流”，再加上若干“异常流”（中途断网、返回键、重复提交）。

4. 错误推测

根据经验猜哪里容易出错：快速连点按钮、输入超长文字、输入空格和特殊字符（' " < >）、旋转屏幕、切到后台再回来、没有网络、列表为空。

写好用例的七条规则

  1. 一条用例只测一件事。“输入错误密码和错误手机号”要拆成两条。
  2. 描述写目的：“密码错误时登录失败”，而不是“测试登录”。
  3. 前置条件写清状态：是否已登录、处于哪个页面、需要什么数据。
  4. 步骤编号、具体：写出实际输入的数据，“输入错误密码”不如“密码输入 abc00000”。
  5. 预期结果可判断：写出具体的提示、跳转、数据变化。“系统正常”是不合格的预期结果。
  6. 编号有规律：样卷样例用“1.1.1”三级编号，可理解为“模块.功能点.序号”。
  7. 测试结果如实填写：通过 / 不通过；不通过时在备注或缺陷表中写明实际结果。被测 App 可能存在缺陷，如实发现并记录它们，正是测试的价值。
易错提醒：只写不测

样卷标题是“编写并执行测试用例”。“测试结果”一列必须是你在模拟器上真实操作后得出的结论。凭感觉全部填“通过”，一旦被测 App 中存在的缺陷被你漏掉，相关用例的得分就没有了。

06执行测试：模拟器操作要点

  • 安装被测 APK：启动模拟器后，把 APK 文件拖到模拟器窗口上即可安装；也可以用命令 adb install 路径\xxx.apk。
  • 截图：模拟器右侧工具栏的相机图标可以截图，保存位置可在 Extended controls → Settings 中设置；Windows 自带 Win + Shift + S 也可以。截图时就按“模块_功能_序号”命名，写手册时能直接找到。
  • 旋转屏幕：右侧工具栏的旋转按钮。
  • 断网测试：模拟器下拉通知栏关闭 Wi-Fi 和移动数据，或在 Extended controls → Cellular 中设置。
  • 重置 App：设置 → 应用 → 找到 App → 存储 → 清除数据，可以回到“首次启动”的状态（测引导页时需要）。
  • 传感器：Extended controls → Virtual sensors 模拟摇动、方向变化。

09专项测试：兼容性、传感器、接口

辽宁能力目录中列有兼容性、传感器和接口自动化测试相关内容。以下是训练方法：

兼容性测试

在 Android Studio 的 Device Manager 中再创建两个虚拟设备：一个小屏手机（如 5 英寸）、一个平板，系统版本也选不同的 API 级别。在每台设备上执行核心用例，并重点检查：文字是否被截断、按钮是否被挡住、横屏时布局是否错乱、列表能否滚动。用例写法：

用例编号用例描述前置条件操作步骤预期结果
CP-01小屏设备登录页完整显示5 英寸虚拟设备，Android 10启动 App，观察登录页，弹出键盘所有控件完整显示；弹出键盘后可滚动到登录按钮
CP-02横屏时服务列表正常已登录，进入服务预约旋转为横屏列表正常显示，已输入的搜索词不丢失

传感器测试

用模拟器 Virtual sensors 修改加速度，测试：低于阈值不触发、超过阈值触发、连续摇动只弹一次、离开页面后摇动不触发（验证已注销监听）、没有联系人时摇动的处理。

接口自动化测试

手工用 curl 测接口，每次改完代码都要重测一遍，费时又容易漏。可以写一个小程序，把测试清单固化下来，一键全部执行：

ApiTester\Program.cs（控制台应用 .NET Framework）

using System.Net;
using System.Text;

{

    /// 只用 .NET Framework 自带的 WebClient，新建“控制台应用(.NET Framework)”即可运行。
    /// </summary>
    internal class Program
    {
        private static string _base = "http://localhost:5000";
        private static int _pass, _fail;

        static void Main(string[] args)
        {
            if (args.Length > 0) _base = args[0].TrimEnd('/');
            Console.OutputEncoding = Encoding.UTF8;
            Console.WriteLine("被测地址：" + _base + "\n");

            // 编号, 方法, 路径, 请求体（GET 填 null）, 返回中应包含的片段
            Case("API-01", "POST", "/api/customer/login", "{\"phone\":\"13800000001\",\"password\":\"abc12345\"}", "\"success\":true");
            Case("API-02", "POST", "/api/customer/login", "{\"phone\":\"13800000001\",\"password\":\"wrong\"}", "手机号或密码错误");
            Case("API-03", "POST", "/api/customer/login", "{\"phone\":\"13800000005\",\"password\":\"abc12345\"}", "已被禁用");
            Case("API-04", "POST", "/api/customer/login", "{\"phone\":\"\",\"password\":\"\"}", "不能为空");
            Case("API-05", "GET",  "/api/categories", null, "生活照料");
            Case("API-06", "GET",  "/api/services?categoryId=3", null, "康复理疗");
            Case("API-07", "GET",  "/api/services?keyword=" + Uri.EscapeDataString("推拿"), null, "\"data\":[]");   // 中医推拿已下架
            Case("API-08", "POST", "/api/orders", "{\"customerId\":1,\"serviceId\":2,\"quantity\":0,\"appointmentTime\":\"2030-01-01 09:00:00\"}", "数量必须是正整数");
            Case("API-09", "POST", "/api/orders", "{\"customerId\":1,\"serviceId\":2,\"quantity\":1,\"appointmentTime\":\"2020-01-01 09:00:00\"}", "必须晚于当前时间");
            Case("API-10", "GET",  "/api/contacts?customerId=1", null, "王小明");
            Case("API-11", "GET",  "/api/nothing", null, "接口不存在");

            Console.WriteLine("\n共 {0} 条，通过 {1} 条，失败 {2} 条", _pass + _fail, _pass, _fail);
        }

        private static void Case(string id, string method, string path, string body, string expect)
        {
            string text;
            using (WebClient wc = new WebClient())
            {
                wc.Encoding = Encoding.UTF8;
                wc.Headers[HttpRequestHeader.ContentType] = "application/json; charset=utf-8";
                try
                {
                    text = method == "GET" ? wc.DownloadString(_base + path) : wc.UploadString(_base + path, method, body);
                }
                catch (WebException ex)
                {
                    // 404、500 等状态码会进入这里，仍然读取返回内容进行比对
                    if (ex.Response == null) text = "连接失败：" + ex.Message;
                    else using (var sr = new System.IO.StreamReader(ex.Response.GetResponseStream(), Encoding.UTF8)) text = sr.ReadToEnd();
                }
            }
            bool ok = text.Contains(expect);
            if (ok) _pass++; else _fail++;
            Console.WriteLine("{0}  {1,-4} {2,-40} {3}", id, method, path.Length > 40 ? path.Substring(0, 40) : path, ok ? "通过" : "失败");
            if (!ok) Console.WriteLine("        预期包含：{0}\n        实际返回：{1}", expect, text);
        }
    }
}

单元测试

单元测试直接测试代码中的方法，最适合校验规则这类“输入 → 输出”明确的代码。在 Visual Studio 中：解决方案右键 → 添加 → 新建项目 → “单元测试项目(.NET Framework)”（MSTest），添加对 SmartCareDesk 项目的引用，然后编写：

ValidatorTests.cs
using Microsoft.VisualStudio.TestTools.UnitTesting;
using SmartCareDesk;

namespace SmartCareDesk.Tests
{
    [TestClass]
    public class ValidatorTests
    {
        [TestMethod]
        public void IsPhone_11Digits_True()
        {
            Assert.IsTrue(Validator.IsPhone("13800000001"));
        }

        [DataTestMethod]
        [DataRow("")]                // 空
        [DataRow("1380000000")]      // 10 位（边界 -1）
        [DataRow("138000000012")]    // 12 位（边界 +1）
        [DataRow("1380000000a")]     // 含字母
        [DataRow(null)]              // null 不能抛异常
        public void IsPhone_Invalid_False(string s)
        {
            Assert.IsFalse(Validator.IsPhone(s));
        }

        [DataTestMethod]
        [DataRow("abc12345", true)]   // 恰好 8 位，字母+数字
        [DataRow("abc1234", false)]   // 7 位
        [DataRow("abcdefgh", false)]  // 没有数字
        [DataRow("12345678", false)]  // 没有字母
        [DataRow("Ab1!Ab1!", true)]   // 含符号也可以
        public void IsPassword_Cases(string pwd, bool expected)
        {
            Assert.AreEqual(expected, Validator.IsPassword(pwd));
        }
    }
}

测试 → 运行所有测试，“测试资源管理器”中全部为绿色即通过。注意这里如何用 DataRow 一次写出一组边界值——这正是本章前面讲的等价类和边界值方法在代码中的体现。单元测试项目模板依赖 MSTest 的 NuGet 包，断网环境下能否创建，同样需要在熟悉设备时确认。
