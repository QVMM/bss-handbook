01数据库的基本概念

概念通俗解释例子
数据库（Database）一个项目的全部数据放在一起SmartCare
表（Table）一类“东西”的清单，像一张 Excel 工作表Customer 客户表
行（记录）一个具体的东西王秀英这位客户
列（字段）东西的一个属性，有固定的数据类型Phone、BirthDate
主键（PK）每行唯一的编号，不能重复、不能为空CustomerId
外键（FK）引用另一张表主键的列，表示“属于谁”订单表的 CustomerId
约束数据库替你把关的规则手机号唯一、价格不能为负

SQL（Structured Query Language）是和数据库对话的语言，SQL Server 使用的版本叫 T-SQL。SQL 关键字不区分大小写，本手册统一把关键字写成大写，便于阅读。

02SSMS 基本操作

新建数据库与执行脚本

  1. 连接后，在左侧“对象资源管理器”右键“数据库” → “新建数据库”，输入名称，确定。

易错提醒：题目给的脚本先看再执行

湖北样题要求先创建名为“Session1”的数据库，再把脚本导入其中，并且“除试题中有明确要求外，不可修改数据库结构、不可删除数据表、不可添加或删除字段、不可修改数据类型”。执行前先用记事本或 SSMS 打开脚本看开头：有没有 CREATE DATABASE、有没有 USE。如果脚本里没有 USE，而你当前选的是 master，所有表就会建到 master 里——这是赛场上真实发生过很多次的事故。

03数据类型怎么选

数据推荐类型说明
编号INT IDENTITY(1,1)自动递增，插入时不用给值
中文文字NVARCHAR(n)带 N 的类型才能正确存中文；字面量写 N'张三'
固定长度编码CHAR(11)、VARCHAR(20)手机号、订单号这类纯数字/英文
金额DECIMAL(10,2)精确小数，共 10 位，其中 2 位小数
日期DATE只有年月日，如出生日期
日期时间DATETIME精确到约 3 毫秒，比赛够用；也可用 DATETIME2
是/否BIT0 或 1；C# 中读出来是 bool
状态码TINYINT0–255，配合注释说明含义
长文本NVARCHAR(500) 或 NVARCHAR(MAX)投诉内容、描述
图片NVARCHAR(100) 存文件名，或 VARBINARY(MAX) 存图片本身比赛中两种都见过：湖北样题要求“照片存储到系统中、≤100KB”

04建表与约束

建一张客户表
CREATE TABLE Customer (
    CustomerId  INT IDENTITY(1,1) NOT NULL CONSTRAINT PK_Customer PRIMARY KEY,
    Phone       CHAR(11)      NOT NULL CONSTRAINT UQ_Customer_Phone UNIQUE,
    Password    NVARCHAR(64)  NOT NULL,
    RealName    NVARCHAR(20)  NULL,
    Gender      NCHAR(1)      NULL CONSTRAINT CK_Customer_Gender CHECK (Gender IN (N'男', N'女')),
    BirthDate   DATE          NULL,
    Status      TINYINT       NOT NULL CONSTRAINT DF_Customer_Status DEFAULT (1),
    CreatedAt   DATETIME      NOT NULL CONSTRAINT DF_Customer_CreatedAt DEFAULT (GETDATE())
);
约束作用违反时
PRIMARY KEY唯一且非空插入重复编号报错
UNIQUE该列不能重复注册重复手机号时报错（C# 中捕获后提示“已注册”）
NOT NULL必须有值不给值报错
CHECK值必须满足条件性别写“未知”报错
DEFAULT不给值时的默认值—
FOREIGN KEY ... REFERENCES值必须在另一张表的主键里存在给不存在的客户下单报错；删除有订单的客户报错

约束名（如 PK_Customer、UQ_Customer_Phone）建议按“类型_表_列”的规则手动起名，出错时一眼就能看出是哪条规则。

修改表结构
ALTER TABLE Customer ADD Email NVARCHAR(100) NULL;          -- 加列
ALTER TABLE Customer ALTER COLUMN RealName NVARCHAR(30) NULL; -- 改类型
ALTER TABLE Customer DROP COLUMN Email;                      -- 删列

05ER 图与数据库设计

ER 图（实体—关系图）用图形描述“有哪些表、表之间什么关系”。拿到需求时先画 ER 图，再写建表语句，能避免返工。题目如果提供了 ERD（湖北样题模块 A 就附有 ERD.pdf），你要能读懂它。

三种关系

关系含义怎么建表例子
一对多（1:N）一个 A 对应多个 B，一个 B 只属于一个 A在“多”的一方加外键一个客户有多个订单 → ServiceOrder.CustomerId
多对多（M:N）一个 A 对应多个 B，一个 B 也对应多个 A建一张“中间表”，含两个外键服务人员与技能 → StaffSkill(StaffId, SkillId)
一对一（1:1）一一对应外键加 UNIQUE，或合并成一张表客户与其健康档案

规范化：三条朴素的规则

  1. 一个格子只放一个值（第一范式）：不要在一个字段里存“助浴,助餐,陪诊”。需要多个值就拆成多行或另建表。
  2. 每个字段都完整依赖主键（第二范式）：中间表 StaffSkill(StaffId, SkillId) 里不要放 StaffName，因为姓名只依赖 StaffId。
  3. 不存“能算出来”或“能查出来”的冗余信息（第三范式）：订单表存 ServiceId 就够了，不要再存服务名称和分类名称。

例外：订单金额 Amount 虽然能用“单价×数量”算出来，但服务价格以后可能调整，订单要记录“下单当时的金额”，所以保留。这类有业务理由的冗余是合理的——能说清理由即可。

数据字典

数据字典是对每张表每个字段的文字说明，世赛能力标准中明确列出了它。格式很简单：

字段类型允许空约束说明
OrderIdINT否PK，自增订单编号
OrderNoVARCHAR(20)否UNIQUE订单号，SO + 下单日期 + 4 位序号
StatusTINYINT否默认 00 待支付、1 已支付、2 已完成、3 已取消
练习 5-1　设计一个小库

为“社区活动报名”设计数据库：活动（名称、时间、地点、人数上限）、居民（姓名、手机号、出生日期）、报名记录（谁报了哪个活动、报名时间、是否签到）。要求：画 ER 图，写数据字典，写出全部 CREATE TABLE 语句（含主键、外键、唯一、检查、默认约束）。思考：同一居民不能重复报名同一活动，用什么约束实现？

提示

报名记录表是活动与居民之间的中间表（多对多）。防止重复报名：在 (ActivityId, ResidentId) 两列上建联合唯一约束：CONSTRAINT UQ_Signup UNIQUE (ActivityId, ResidentId)。人数上限不能用简单约束实现，要在程序里插入前先查询已报名人数。

07查询基础：SELECT

USE SmartCare;

SELECT * FROM Customer;                                -- 全部列（练习可以，正式代码中写明列名）

SELECT TOP 3 * FROM CareService ORDER BY Price DESC;
SELECT DISTINCT CategoryId FROM CareService;

08常用函数

SELECT GETDATE();                                         -- 当前日期时间
SELECT CONVERT(CHAR(10), GETDATE(), 120);                 -- 'yyyy-mm-dd'（120 是 ODBC 规范格式）
SELECT CONVERT(CHAR(7), CreatedAt, 120) FROM ServiceOrder; -- 'yyyy-mm' 按月统计常用
SELECT CONVERT(CHAR(16), CreatedAt, 120) FROM ServiceOrder;-- 'yyyy-mm-dd hh:mi'
SELECT DATEADD(DAY, 7, GETDATE());                        -- 7 天后
SELECT DATEDIFF(YEAR, BirthDate, GETDATE()) FROM Customer; -- 粗略年龄（只看年份差）
SELECT ISNULL(RealName, N'未填写') FROM Customer;          -- 空值替换
SELECT LEN(N'智慧康养');                                    -- 4
SELECT CAST(Price AS INT) FROM CareService;                -- 类型转换
SELECT ServiceName,
       CASE WHEN Price >= 150 THEN N'高价' WHEN Price >= 50 THEN N'中价' ELSE N'低价' END AS 档次
FROM CareService;                                          -- 条件表达式
SELECT OrderNo,
       CASE Status WHEN 0 THEN N'待支付' WHEN 1 THEN N'已支付'
                   WHEN 2 THEN N'已完成' WHEN 3 THEN N'已取消' END AS 状态
FROM ServiceOrder;
训练建议：日期格式在哪里转

题目要求界面显示 YYYY-MM-DD。你可以在 SQL 里用 CONVERT(CHAR(10), 列, 120) 转成字符串，也可以把 DateTime 取到 C# 后用 ToString("yyyy-MM-dd")。推荐后者：数据库只负责给出正确的数据，格式交给界面。但按月统计分组时，在 SQL 里转换更方便。

09聚合与分组统计

SELECT COUNT(*) FROM Customer;                     -- 行数
SELECT COUNT(RealName) FROM Customer;              -- 非空的 RealName 个数（11）
SELECT SUM(Amount), AVG(Amount), MAX(Amount), MIN(Amount) FROM ServiceOrder;

-- 按状态分组
SELECT Status, COUNT(*) AS Cnt, SUM(Amount) AS Total
FROM ServiceOrder
GROUP BY Status;

-- 按月统计（不含已取消）
SELECT CONVERT(CHAR(7), CreatedAt, 120) AS [Month], COUNT(*) AS OrderCount, SUM(Amount) AS Revenue
FROM ServiceOrder
WHERE Status <> 3
GROUP BY CONVERT(CHAR(7), CreatedAt, 120)
ORDER BY [Month];

-- HAVING：对分组结果再筛选
SELECT CustomerId, COUNT(*) AS Cnt
FROM ServiceOrder
GROUP BY CustomerId
HAVING COUNT(*) >= 3;          -- 练习库中结果为客户 1、2、3、4、6、7

WHERE 在分组前筛选行，HAVING 在分组后筛选组。SELECT 中出现的非聚合列，必须出现在 GROUP BY 中。

10多表连接：JOIN

订单表里只存了客户编号和服务编号。要显示“客户姓名、服务名称”，就需要把表连接起来。

-- 内连接：两边都匹配上的行才出现
SELECT o.OrderNo, c.RealName, s.ServiceName, o.Quantity, o.Amount,
       o.AppointmentTime, o.Status
FROM ServiceOrder o
INNER JOIN Customer c    ON o.CustomerId = c.CustomerId
INNER JOIN CareService s ON o.ServiceId = s.ServiceId
ORDER BY o.CreatedAt DESC;

-- 三表以上：服务 + 分类
SELECT s.ServiceName, cat.CategoryName, s.Price
FROM CareService s
JOIN ServiceCategory cat ON s.CategoryId = cat.CategoryId;

-- 左连接：左表全部保留，右表匹配不上的列为 NULL
SELECT s.ServiceName, COUNT(o.OrderId) AS OrderCount
FROM CareService s
LEFT JOIN ServiceOrder o ON s.ServiceId = o.ServiceId
GROUP BY s.ServiceName
ORDER BY OrderCount DESC;

表别名（o、c、s）让语句更短。左连接中计数要写 COUNT(o.OrderId) 而不是 COUNT(*)，否则没有订单的服务也会计成 1。

练习 5-5　连接综合

  2. 找出从未下过单的客户。

  4. 列出所有“待处理”的投诉：投诉内容、客户姓名、服务名称、投诉时间（yyyy-MM-dd HH:mm）。
  5. 按客户统计消费金额（只算已支付和已完成），取前 3 名。

11分页查询

比赛中“每页 10 条、首页/上一页/下一页/尾页/跳转”出现频率很高（湖北样题有 4 个界面要求分页）。SQL Server 2012 起支持 OFFSET ... FETCH：

DECLARE @PageIndex INT = 2, @PageSize INT = 5;   -- 第 2 页，每页 5 条

SELECT CustomerId, RealName, Phone
FROM Customer
ORDER BY CustomerId                                -- 分页必须有 ORDER BY
OFFSET (@PageIndex - 1) * @PageSize ROWS
FETCH NEXT @PageSize ROWS ONLY;

SELECT COUNT(*) FROM Customer;                     -- 总条数，用来算总页数

UPDATE Customer SET Status = 0 WHERE CustomerId = 5;
易错提醒：没有 WHERE 的 UPDATE / DELETE

UPDATE CareService SET Price = 0 会把所有服务改成 0 元。养成习惯：先写 SELECT * FROM 表 WHERE 条件 确认查到的就是你要改的那几行，再把 SELECT * 换成 UPDATE/DELETE。练习时改坏了，重新执行练习库脚本即可恢复。

BEGIN TRY

CREATE VIEW vOrderDetail AS

14健康数据统计（为手机端图表做准备）

-- 客户 1 的血压记录，按时间升序（画折线图用）
SELECT CONVERT(CHAR(10), MeasuredAt, 120) AS [Day], Value1 AS Systolic, Value2 AS Diastolic

-- 平均值与偏高次数
SELECT CAST(AVG(Value1) AS DECIMAL(6,1)) AS AvgSys,
       CAST(AVG(Value2) AS DECIMAL(6,1)) AS AvgDia,
       SUM(CASE WHEN Value1 >= 140 OR Value2 >= 90 THEN 1 ELSE 0 END) AS HighTimes,
       COUNT(*) AS Total
FROM HealthRecord
WHERE CustomerId = 1 AND RecordType = N'血压';
