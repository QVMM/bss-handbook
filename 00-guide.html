如何使用本手册

这一章回答三个问题：每天该怎么学；手册和你手上的资料包怎么配合；拿到自己省份的技术文件后要做哪些“对表”工作。读完大约 30 分钟。

01一天的学习是什么样子

本手册的每个学习章节都按“讲解 → 照着敲 → 小练习 → 过关检查”组织。一个 1.5 小时的工作日学习时段，建议这样用：

时段做什么要点
0–10 分钟复习：翻错题本，把昨天记下的 3–5 个写法默写一遍默写错了就红笔改，旁边打一个记号，下次重点看
10–40 分钟读手册当天内容，边读边把示例代码敲进电脑并运行运行结果和手册写的不一样时，先自己找 5 分钟原因，再看“常见错误”
40–80 分钟做当天的练习题，先不看答案卡住超过 15 分钟就看提示；看完答案后要关掉答案重新写一遍
80–90 分钟写训练日志：今天学了什么、哪里卡住、明天做什么日志模板见第 15 章

周末的 3 小时时段则用来做一个“小项目”（每章末尾都有），或者在后期做整套样卷的计时训练。

训练建议：错题本

赛场不允许带书籍和参考资料（辽宁文件“赛场禁止自带使用的设备和材料清单”中列有“书籍和参考资料”）。也就是说，比赛时所有写法都得靠你记住，或者靠开发工具自带的提示和帮助。所以从第一天起就准备一个专门的本子，按“数据库 / C# / WinForms / 接口 / Android / 测试”分区，记录：

  • 自己写错过的代码（错的写法 + 正确写法 + 为什么）；
  • 每次都要查的写法（例如连接字符串、SharedPreferences 的读写）；
  • 做样卷时丢分的原因。

到赛前一个月，这个本子就是你最值钱的复习资料。

03拿到自己省份的文件后，先做“对表”

本手册以辽宁 2026 年文件为主线，因为它是目前资料包里最新、最完整的人社口省赛文件。但你参加的可能是另一个省、另一年的比赛。拿到你自己赛区的技术文件（通常叫“技术工作文件”“技术文件”或“竞赛规程”）后，请用下面这张表逐项核对，把不同之处用红笔写在本手册对应章节旁边。

核对项辽宁 2026 文件的写法你的赛区写的是
模块数量与名称A 软件功能开发、B 手机功能开发、C 应用测试
每个模块时长各 2 小时，共 6 小时，1.5 天
分值与权重A 40、B 40、C 20；测量 94、评价 6
数据库文字写“MySQL 或 SQL Server”；设备清单只列 SQL Server 2022 及以上
桌面开发平台.NET，Visual Studio 2022 及以上，.NET Framework 4.8 及以上
移动开发Android，Android Studio 2023.2.1 及以上（文件未指定 Java 还是 Kotlin）
模块 B 的数据来源“本模块数据来源 Modul1 接口”
是否联网 / 能否用第三方库文件未专门说明；禁止自带“额外的软件”
开发语言（中文 / 英文）样卷界面为中文
提交方式源码压缩为 Modul1.zip、Modul2.zip（含 APK）、Module3.zip，提交至 U 盘
正式赛题与样卷的关系裁判长对样题内容进行 30% 以内的修改
是否包含 Python / 数据分析未出现

对表之后，如果发现你的赛区与辽宁差异很大（例如还是湖北 2020 那样 A、B 各 3 小时、提供现成的 WebApi.exe），也不用慌：本手册教的技能是一样的，只是第 13 章的时间分配要按你的赛制重算。

04学习顺序为什么是这样

本手册的学习路径是：

  1. 计算思维与应用结构（第 03 章）——先知道“一个商务软件由哪几块组成”；
  2. C# 语言（第 04 章）——所有桌面端和接口代码的基础；
  3. SQL Server（第 05 章）——数据放在哪里、怎么查；
  4. WinForms 桌面应用（第 06 章）——模块 A 的主体；
  5. Web API（第 07 章）——把数据开放给手机端，是模块 A 与模块 B 之间的桥；
  6. Android（第 08 章）——模块 B；
  7. UML 与需求分析（第 09 章）——读懂题目、规划作品、冲击更高层级比赛；
  8. 测试与操作手册（第 10 章）——模块 C。

其中第 09 章和第 10 章不必等到最后才学：训练计划里，测试用例的写法从 WinForms 阶段就开始穿插练习，因为“给自己的作品写测试用例”本身就是查漏补缺的最好方法。

说明：为什么 Android 用 Java

辽宁文件只写了“使用 Android 开发手机 APP 功能”“使用 Android 开发语言”，没有规定 Java 还是 Kotlin。本手册选择 Java，原因有三：Java 和 C# 的语法非常接近，学完 C# 再学 Java 几乎只需要适应差别；Android 官方文档与大量参考资料对 Java 支持完整；Java 写网络请求、JSON 解析都可以只用 Android 系统自带的类，不依赖额外下载的库。已经熟悉 Kotlin 的同学可以继续用 Kotlin，第 08 章的思路完全适用。

05关于“能拿奖”

本手册不会告诉你“照做就能拿金牌”，因为比赛的结果还取决于同场对手、临场状态和当年题目。但我们可以很具体地描述有竞争力的作品在评分表上是什么样子（第 01 章会细讲）：

  • 在规定时间内，题目要求的每个界面都“能打开、能操作、数据正确”，没有一个功能是空壳；
  • 模块 A 的接口先于手机端完成，并且接口的字段名、格式与手机端一一对应，手机端不会因为接口问题整块丢分；
  • 所有输入都有校验和明确提示，日期一律 YYYY-MM-DD，列表超出时有滚动条，缺图显示默认图片——这些“小要求”每个都是分；
  • 数据操作干净：增删改之后列表即时刷新，数据库里的数据真的变了；
  • 测试用例覆盖了题目规定的每个功能模块且数量达标，操作手册结构完整、图文对应。

能稳定做到这些，就具备了在省赛争夺奖牌的实力；在此基础上把速度再提高三成、把界面和代码质量做到“高于行业标准”，就是冲击国赛的方向。
